# Public pages and the installed app

Conventions for the prerendered public pages, the service worker, the theme set before the first paint, and the app installed on a phone or computer. The general rules are in `AGENTS.md`.

- Public pages (`publicPages` in `app/lib/configs/page.ts`, and `prerender` in `react-router.config.ts`) are rendered at build time in English and must not wait for Firebase Auth or touch browser APIs (`window`, `localStorage`, `document`) while rendering; do that in effects. A new public page goes in both lists and in `PUBLIC_PAGES` in `public/sw.js`.
- `public/sw.js` must never serve an outdated app while online: pages stay network-first, and it leaves cross-origin requests (Firebase, Firestore) alone. When you change what it caches or how, bump the cache names (`pages-v2`, `assets-v1`) so old caches are dropped.
- Theme: `ThemeHead` (`app/components/layouts/theme-head`) runs before the first paint on every page, including the start-up fallback: it applies the saved theme and size and creates the single `theme-color` tag and the tab's icon (`favicons`, the logo that stands out on the theme), which `ThemeProvider` keeps in step with the app's theme. Don't render any of them from React or route `meta`/`links`: React would add a second copy. The installed app's status bar on iPhone is see-through in both themes (`black-translucent`, in `appMeta`, since iOS reads it only from the first HTML) iOS 26 blurs the page's top edge under it, so content placed below the status bar uses `--top-inset` (`app/styles/tailwind.css`), never `env(safe-area-inset-top)`, to stay clear of that blur at rest. Show the logo with `Logo` (`app/components/base/logo`), which follows the theme the same way.
- The installed app never shows the landing page: the inline script in `app/components/layouts/theme-head` leaves `/` before the first paint, and `middleware` redirects in-app visits to it (`isStandalone`). It opens on the person's start page instead (also the first page of a session at the manifest's `/notes`, and after signing in), except that a relaunch within an hour of going to the background returns to the last page (`last-visit` in `localStorage`, kept by `useRememberLastVisit`), since a phone may unload a backgrounded app. The start page and menu order are saved on the profile (`navOrder`, `startPage`); the start page is also kept in `localStorage` (`app/lib/constants/navigation.ts`) because the script runs before the profile loads.
- Installing: the manifest comes from `scripts/generate-manifest.mjs` (run by `pnpm build`); app-wide meta tags come from `withAppMeta` (`app/lib/constants/metadata.ts`), which a route with its own `meta` must use.
