# UI patterns

Conventions for list pages, detail forms, floating surfaces and Tailwind 4. The general rules are in `AGENTS.md`.

- A list page renders `Collection` (`app/components/base/collection`): loading and empty states, pinned and other sections, the person's archived items folded away at the bottom (`archivedBy`, per person like `pinnedBy`), newest first, and filtering by `?q=` (set by "See all" in the navbar's global search, `layouts/navbar/search.tsx`). Cards open through a link that covers the card (see `notes/card.tsx`), and masonry cards are `w-full sm:w-80`.
- A detail form saves with `useAutosave` and a `save()` that writes only what differs from the stored document, so it can run any time (idle, leaving, the Save button). It takes the stored item through `useStoredValues` (`defaultValues` plus the hook, never `values` with `keepDirtyValues`, which kept a stale copy and wrote deleted entries back), with `mergeById` for lists whose items have an `id`. New items are created when leaving with content, never discarded behind a prompt. Show `SaveStatus` next to the date, and lock every input for read-only users.
- Each list page, detail page and Settings has a screen guide (a detail page's shows itself only once the item exists): a short walk over its real controls, shown the first time the page opens and again from **Page guide**, which takes How to use's place in the account menu once signed in (How to use itself stays public, with **Show me in the app** per section). Its steps are listed in `app/lib/constants/screen-guide.ts` and point at `data-guide` markers on the controls; its text is `guide.<guide>.<step>` in both languages. A page turns its guide on with `useScreenGuide` (`app/components/base/screen-guide`). Steps whose control isn't on screen are left out, so keep a marker on the control when moving or renaming it, and add a step when a page gains a main control. The end-to-end tests mark every guide as seen (`newDevice` in `tests/e2e/helpers.mjs`); list a new guide there too.
- Surfaces that float above the page (cards, bars, menus, popovers, tooltips, toasts, sheets) use the liquid glass material, `glass-surface` (`app/styles/tailwind.css`), plus `glass-thick` for sheets and dialogs over a dimmed page and `glass-float` for panels content scrolls under. A floating bar or button whose content scrolls past its edges and gaps (the detail action bars, the bottom tabs, the list create button) gets `glass-halo`: a subtle blur that fades out around it like a shadow, with `--halo-inset` when the element pads its content. Change the look through its variables (`--glass-*`), not per component, and keep its solid fallback for reduced transparency and more contrast.
- Tailwind 4 is configured in CSS only: theme, plugins and the `dark` variant live in `app/styles/tailwind.css`. Don't add a `tailwind.config.*` or `postcss.config.*`. Other CSS files that use theme values start with `@reference './tailwind.css'` and use `--theme(...)`.
- Tailwind 4's `space-y-*` adds a bottom margin, which does nothing on an inline element such as a `<label>`. For a stack that starts with a label, use `[&>:not([hidden])~:not([hidden])]:mt-*` (the v3 rule, as in `app/components/base/input/`); elsewhere prefer `flex`/`grid` with `gap-*`.
